# ADR 0002: Synthetic development foundation before launch decisions

Superseded in part by ADR 0003 (`comp-server/doc/adr-0003-grounded-answers-development.md`) for grounded answers.

Status: accepted engineering boundary; launch decisions pending.

The supplied roadmap has no named scholarly approvers, licensed reviewed corpus, jurisdiction-specific safeguarding playbook, consent design approval or finalized launch market/curriculum. This increment supports adult-operated synthetic development only. It must not be distributed as a child product.

Use English UI provisionally and the roadmap's ages 7–11 planning assumption; neither selects a launch market or infers family practice. Use the supplied Robert default skin and exact body/face clips. Voice, generative answers, generative stories and live Unity embedding are unavailable. Q&A exercises request/replay/deletion transport and returns a fixed unavailable message; no model knowledge or invented religious citations are used.

The local backend's bounded memory store is an explicit prototype adapter. It is not the production system of record. The next approved data increment must implement PostgreSQL transactions, append-only rewards, ownership/consent enforcement, export/deletion and Redis coordination before real users or multiple API workers. Published corpus retrieval will use pgvector only after source/reviewer/governance gates pass. Object storage and provider adapters remain disabled until their privacy boundaries are approved.

The development token is a local operator guard, not authentication, guardian consent or a parental gate. The app defaults to offline orientation without API requests. Enter only synthetic test text. Test coverage proves software behavior within this boundary; it does not establish scholarly, safeguarding, privacy, legal or device approval.
